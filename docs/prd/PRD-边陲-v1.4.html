三句话讲清产品：

  1. 它是"设计游戏"，不是"操作游戏"。居民全自动工作，玩家的输入只有四类：圈区域、放建筑、调时间、看信息。乐趣来自"我设计的秩序是否成立"。
  2. 它有明确的输赢。撑过 12 天即胜利，全员倒地即失败。这使它对新手有终点、对老手有可重复挑战的空间。
  3. 它的门槛是零。双击打开即玩，无账号、无下载、无联网。这让它适合作为"发给别人就能玩"的作品，而不是需要安装的独立游戏。
本 PRD 的写法约定 每条需求带唯一 ID（FR-x.y / AC-x），可直接作为开发任务与测试用例的锚点。数值一律标注单位与时间基准（游戏内分钟 / 格 / 像素）。凡涉及"手感"的判断，均给出可测量的替代指标，避免"感觉不对"这类无法验收的表述。

02 / DEFINITION产品定义

2.1 一句话定义

《边陲》是一款以"规则设计"为核心动词的轻量殖民地模拟游戏：玩家用有限的石料与木料规划一块边境落脚点，三名自动工作的幸存者在其中采集、耕作、建造、战斗，玩家需要在 12 天内让这个系统不崩溃。

2.2 设计目标

目标按优先级排列，冲突时上位优先。

2.3 非目标（明确不做）

写清"不做什么"比写"做什么"更能保护排期。以下为本版主动放弃的方向：

非目标原因
多人 / 联机与"单文件离线"的核心约束冲突，需要服务端，收益不匹配成本。
自由建造的 3D 视角俯视 2D 已足够表达"布局决策"，3D 会让数值可读性下降。
长线养成（科技树 / 跨局继承）v1.0 定位是"一局 30 分钟的完整闭环"，长线会稀释单局张力。
剧情 / 对话 / 角色叙事居民是"系统单元"而非"角色"，叙事会引导玩家去做情感投射，与设计游戏的核心动词竞争注意力。
移动端触屏优化本版仅保证桌面浏览器可用；触屏交互另立需求（见 §11.3）。
Mod / 脚本扩展单文件架构下无稳定扩展点，强行支持会破坏零依赖约束。

2.4 目标用户

角色特征核心诉求占比预估
P1 · 模拟游戏老手玩过《环世界》《缺氧》《放逐之城》，熟悉"优先级 + 需求"模型要的是可优化的系统：布局效率、资源曲线、防守容错。会主动找最优解。35%
P2 · 好奇的轻度玩家不玩硬核模拟，被"网页一点就开"吸引要的是低门槛的成就感：看得懂在发生什么，第一次能赢。45%
P3 · 作品浏览者通过分享链接进来，停留时间短要的是30 秒内明白"这是什么"：截图好看、引导清楚、能立刻动手。20%

P2 是设计基准用户。所有引导、文案、默认参数都按"没玩过模拟游戏的人"校验；P1 的深度需求通过可读的数值与可优化的布局满足，而不是增加系统复杂度。

2.5 体验支柱

PILLAR 01
秩序感

玩家画下的每一块区域、放下的每一堵墙，都会立刻改变居民的行为路径。世界对规划有即时且可见的响应。

PILLAR 02
紧绷感

资源永远差一点。石料要么修墙、要么造炮；人要么生产、要么建设。任何时候都不能"全都做"。

PILLAR 03
可读性

屏幕上的每个数字、每条日志、每根血条都在回答"为什么"。信息不做隐藏，只做分层。

三条支柱互为约束：为了可读性必须减少系统数量；为了紧绷感必须让资源稀缺；为了秩序感必须让玩家操作有快速反馈。任何新功能若同时违反两条以上，应当被拒绝。

3.1 差异化定位

一句话："用 12 天讲完一个完整的殖民地故事，用一个 HTML 文件送到任何人面前。"

  • 对 P1（老手）：提供被压缩到极致的系统——每个数字都能被优化，但没有冗余机制需要学习。是"通勤路上可以打一局"的环世界。
  • 对 P2（轻度）：提供有限目标 + 强引导。不需要理解"优先级矩阵"，只需要理解"石头要用来修墙"。
  • 对 P3（浏览者）：提供 30 秒内可完成的第一个有意义操作，以及一张能当封面的中局截图。
定位风险 压缩系统会同时削弱两端的体验：老手可能觉得"太浅"，轻度玩家仍可能被"需求条"吓退。缓解方式：把深度放在"布局效率"（可无限优化的空间）而非"机制数量"；把门槛放在"引导文案"（可迭代）而非"简化机制"（会伤及支柱）。

04 / CORE LOOP核心循环

4.1 三层循环

本作刻意把循环切成三层，对应三种不同的思考节奏。玩家在 30 分钟内会反复穿梭于三层之间，这是"不累但不无聊"的关键。

LOOP A · 秒级
观察与纠错

看到某人在发呆 / 某个需求条变红 → 点开他 → 判断原因（没活干？没料？路被堵？）→ 补一个区域或建筑。
时长：5–20 秒 / 次

LOOP B · 分钟级
生产与建设

缺木 → 砍树获得木 → 木变床/门/餐桌 → 生活品质上升 → 心情上升 → 工作效率上升。
时长：2–5 分钟 / 次

LOOP C · 天级
威胁与备战

日志提示"第 N 天有袭击" → 修墙、造炮、备粮 → 撑过袭击 → 清点损失 → 进入下一天。
时长：3–6 分钟 / 天

4.2 一个游戏日的时间切片

以第 4 天（已有围墙、首次双人袭击）为例，说明玩家注意力如何被分配：

4.3 玩家输入预算

为保证"设计游戏"的定位，任何一分钟内的有效操作数应落在以下区间。这是反向约束：如果某个系统迫使玩家每分钟点击 10 次，说明它设计错了，应当改成自动化。

阶段操作 / 分钟主要操作类型
开局（D1）4–8圈仓库区、放床、放篝火、开农田
建设期（D2–D5）2–5连续摆墙、补门、造炮
稳态（D6–D10）1–3补漏、看信息、临时调整
高压（袭击中）0–2几乎不操作，只看结果（这是设计意图）

注意最后一行：袭击期间玩家几乎无事可做是刻意的。战斗的胜负在袭击开始前就由"墙、炮、人"决定了。玩家在战斗中唯一能做的是观察，这正是"设计游戏"的核心表达——你无法临场救火，只能提前设计。

05 / SYSTEM SPEC系统规格

本章逐系统给出规格。每个系统包含：职责（它解决什么问题）、规则（可验收的实现约束）、参数（数值表）。参数表中标注 已实现 的为当前构建实测值，可直接作为回归基线。

5.1 世界与地图 已实现

职责：提供一个足够大、能排出多种地貌节奏的封闭空间；保证关键资源可达、威胁有公平的进入路径，并让同一张图看第三遍时仍然有可读的细节。

5.1.1 尺寸、地形与可达性

FR-5.1.1 地图尺寸72 × 52 格 = 3744 格；单格 34 CSS 像素（逻辑坐标 × 缩放倍率 0.4–2.4）。地图为硬边界，单位不可越出。
FR-5.1.2 地形种类8 种：草地 GRASS、沙地 SAND、泥土 DIRT、水域 WATER、岩壁 ROCK、花甸 MEADOW、碎石滩 GRAVEL、湿地 MARSH。可通行性见 5.1.3。
FR-5.1.3 程序化生成基于 6 组独立噪声（高程/岩体/植被/湿度/域扭曲/湖盆）+ 播种随机数。同一种子必须生成完全相同的世界（含地貌、植被、遗迹、散落物位置），用于复现、分享与回归测试。
FR-5.1.4 出生地保护地图中心半径 8.5 格内强制清空岩壁/水域/湿地为草地，6 格内不出现沙地；5.4 格内不生成植被。保证开局有 220 格以上的干净建造面。
FR-5.1.5 资源分布伐木资源由密度场 dens = clamp((forest − 0.52) × 5.2 + 湿度 × 0.22, 0, 1) 决定，dens > 0.20 处成林；矿区由 2~3 片低频"山体"噪声 + 细长"岩脊"构成，山脚为碎石滩。三者叠加使地图同时具备密林、疏林草甸、裸岩台地三种可辨识区域。
FR-5.1.6 初始散落物资中心 3 格范围内必有 2 处散落物：60 木材 + 10 食物。与仓库区初始物资（见 FR-5.8.2）共同构成开局资源。
FR-5.1.7 连通性保证生成后从地图中心做 8 向洪水填充，标记"实际可达"格。所有敌人生成点必须位于可达集合内，且只允许从可达的地图边缘进入，杜绝"敌人刷在封闭岩体里永远走不过来"的软锁。
FR-5.1.8 水系地图含 1 片大湖（椭圆，最短半径 ≥ 9 格）+ 1 条蜿蜒溪流。溪流自地图北缘汇入大湖，河道半宽 1.1~1.8 格，沿程偏移由正弦 + 噪声共同驱动，禁止直线。河上必须留 2 处浅滩（沙质涉水点，位于河道 33% 与 64% 处），保证水系不切断地图连通性。
FR-5.1.9 地类抗噪分类完成后执行 2 轮平滑：孤立单格（同色邻居 ≤ 1 且异色邻居 ≥ 3）被并入多数邻居。水域与岩壁不参与该过程，避免湖泊被"补丁化"。目标：消除"马赛克撒点"式噪点，同时保留自然的不规则边缘。
FR-5.1.10 荒野遗迹地图外围随机放置 3 处遗迹（距出生地 ≥ 13 格、可通行、非湿地）。每处提供木材/石料/食物的探索奖励，首处额外含 4 份熟食，用于鼓励玩家向地图外围扩张。
历史缺陷 · 已修复 v0.9 曾出现"殖民地永远和平"的问题：袭击者在岩体包围的死角生成，寻路失败后原地僵持，表现为连续多天无袭击。根因是生成点只校验了"可通行"而未校验"与殖民地连通"。FR-5.1.7 为永久性约束，任何改动生成逻辑的提交必须回归此用例。

5.1.5 水面与植被的专项规格

FR-5.1.11 岸线连续性水面不得以"逐格方块"呈现。必须由有符号距离场（距岸格数，水正陆负，BFS 求值）+ 双尺度噪声扰动（±0.70 / ±0.22 格）生成连续岸线，再以 0.34 像素/世界像素的采样率逐像素着色后双线性上采样。
FR-5.1.12 水深表现颜色 = 距岸距离 × 0.55 + 湖底高程 × 3.0（权重可调），经 sqrt 映射后四段渐变（浅滩青 → 湖蓝 → 深蓝 → 幽蓝），湖心不得出现同心环。浅滩 0.30 格内叠加半透明白边模拟浪花。
FR-5.1.13 植被分层针叶树 5 层叠翠（每层左受光/右背光双色），阔叶树 7 瓣树冠 + 2 点高光 + 横椭圆比（宽:高 ≈ 1.3:1）；树干、落影方向统一为"光自左上"。枯木单独一套枝干骨架。
FR-5.1.14 绘制预算地图生成 ≤ 400 ms（实测 249 ms @ 72×52）；地形烘焙 ≤ 400 ms（实测 241 ms @ 1.6× 超采样）；水面噪声须预烘焙到 1/4 格网格后双线性采样，禁止逐像素调用 fbm。
FR-5.1.15 局部重绘采矿等改变地形的操作只重绘 3×3 格并补画过渡/岩壁/AO，不得整图重烘焙（单次 < 16 ms）。

5.4 心情模型 已实现

职责：把分散的系统（食物质量、睡眠质量、居住条件、战斗伤害、天气）压缩成单一可读数字，让玩家有一个"综合健康度"指标。

心情不是即时值，而是向目标值平滑逼近（lerp 系数 0.28），避免数值跳变造成情绪困扰：

mood_target = 52 − 20 (饥饿 < 18) | − 10 (饥饿 < 35) − 18 (精力 < 18) | − 8 (精力 < 35) − 14 (hp < 60) − 25 (倒地) − 6 (就地睡) | + 5 (床上睡) + 5 (篝火 4 格内) − 4 (1.6 格内聚众 ≥ 2 人) − 4 (降雨) + moodBias (个体差异)
mood ← clamp( lerp(mood, mood_target, 0.28), 0, 100 )

5.5 工作调度 已实现

职责：这是整个产品的技术核心。玩家不派活，所以"谁去干什么"必须由一个稳定、可预测、不打架的调度器决定。调度器的质量直接决定玩家是否信任这个系统。

5.7.2 区域

区域规则
仓库区拖拽圈划。只有落在仓库区内的物品才计入资源账目。移出仓库区会导致账目扣减。仓库区是建造扣料的唯一来源。

5.7.3 撤销与快捷键 v1.2 新增

要解决的问题：建造是"立刻扣料"的，误摆一格墙就要手动拆除、还会损失一半材料。这是高频挫败点，且与 G1（30 秒上手）冲突——新手一定会在前两分钟摆错。

编号需求规则
FR-5.7.5撤销栈每次建造或圈地入栈一条记录，容量 120 条，超出丢最旧；新开局清空。记录的是"这一格之前是什么 + 这次操作动了多少账"，不存整张地图快照。
FR-5.7.6建造回退撤销建造 = 清空蓝图 + 全额退还材料到最近仓库格。若该建筑已不存在（被拆或被毁）则拒绝并提示，不做静默失败。
FR-5.7.7区域回退撤销圈地 = 恢复原区域类型，并按操作时记录的资源差额反向修正账目。原因：把已有物品的格子从仓库区改走，会把区内物品从账上扣减，回退必须补回。若该格已被后续操作改动则拒绝。
FR-5.7.8建筑快捷键1–6 依次对应石墙 / 木门 / 床铺 / 篝火 / 哨戒炮 / 餐桌；再按一次取消当前模式。建造按钮左上角常驻显示对应数字。
FR-5.7.9流速键位迁移数字键改为建造选择后，流速改用 [ / ] 逐级增减（同时解除暂停）。顶部流速按钮保留，不影响鼠标玩家。
为什么不存整张地图快照 3744 个格子，每次操作复制一份的话，内存与序列化成本都不可接受，而且会让"撤销"从瞬时操作变成可感知的卡顿。只记录差异后，单条记录压到几十字节，回退是 O(1)。代价是只能撤销结构改动，不能撤销"时间流逝造成的改变"（居民走动、作物生长）——这是有意划定的边界，也符合玩家直觉。

5.12.4 并发护栏

FR-5.12.6：场上存活来袭者上限 14。达到上限时，新一波袭击被压掉或按剩余额度减员。

护栏解决的是什么 在加入这条之前，实测出现过"第 8 天场上 8 个、第 12 天 26 个"的堆积曲线：一旦某一天没能全歼，下一波就会叠加上来，局面在玩家还没反应过来时就已经不可逆。护栏把它变成一条可理解的失败曲线——你会看到敌人一直压在 14 个，明白"我守不住了"，而不是被一次莫名其妙的雪崩带走。
同时它也是性能护栏：单位数封顶让最坏情况下的模拟开销可控。它不是一个难度旋钮，调难度时不应改动它。

5.16 信息呈现与反馈层 v1.4 新增

v1.3 结束时，科技、医疗、性格、兵种、掩体、指令六个系统都已经在后台运转，但屏幕上没有把它们翻译给玩家： 心情掉到 42，玩家只看到一个 42；鼠标扫过营地只有一个白框；选中居民看不出他要去哪。 外部反馈的原话是「还是很抽象」。本节解决的不是玩法，而是把已经存在的状态变成可读信息。

5.16.4 因果播报

崩溃日志不再只写"精神崩溃了"，而是列出触发链的最多三项原因：饿了很多天 / 连续几夜没睡好 / 伤一直没好 / 跟同伴结了怨 / 刚被打倒过 / 长期淋雨。同理，砸库存的崩溃也会带上原因。

为什么不直接给玩家看数值 数值已经给了（心情账单）。日志要回答的是另一个问题：「为什么偏偏是今天、偏偏是他」。 这两件事必须分开做，否则日志会变成仪表盘，仪表盘会变成没人看的东西。

FR-5.16.9 归因按顺序检测饥饿、精力、伤口、关系、倒地、降雨；不足两项时追加"吃的一直不够"，全无则回退到"情绪积压太久"，保证任何时候都有可读的原因。

10.2 需要关注的诊断指标

  • 首次死亡时间：如果集中发生在第 2–3 天，说明首次袭击强度过高或引导未讲清"要修墙"。
  • 资源归零点：如果石料在第 6–8 天归零且玩家未能恢复，说明采矿效率或石料预算需要调整。

为什么这里不给"精确埋点方案" 一个承诺零请求的单机网页游戏，强行加埋点会违背它的核心承诺。因此本 PRD 把度量定义为观察式验证：用 5–10 名真实用户的可观察行为替代统计数据。这在作品的量级上是更诚实也更有效的做法。
